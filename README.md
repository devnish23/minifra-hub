# Minifra Hub — Setup Guide

**Hub machine**: 192.168.1.109 (your desktop)  
**Endpoints**: 192.168.1.134 · 192.168.1.141 · 192.168.1.142 · 192.168.1.143

---

## What's in this package

| File | Purpose |
|---|---|
| `setup.bat` | One-click: installs deps, builds EXEs, generates cert |
| `dist/minifra-hub.exe` | Hub server — runs on 192.168.1.109, polls VMs via WinRM |
| `dist/minifra-agent.exe` | Windows Service — deployed to each VM for richer monitoring |
| `build/deploy.py` | Pushes agent.exe to all 4 VMs and starts the service |
| `config/hub-config.json` | Credentials + endpoint config |
| `certs/` | Self-signed TLS cert (generated by setup.bat) |

---

## Step 1 — Edit credentials

Open `config/hub-config.json` and set:
- `"password"` for each of the 4 endpoints (their local Administrator password)
- `"auth_token"` — any strong secret, e.g. `mfs-abc123xyz`

---

## Step 2 — First-time setup

On your desktop (192.168.1.109), open a command prompt in this folder:

```
setup.bat
```

This will:
1. Install Python dependencies (fastapi, uvicorn, pywinrm, psutil, pyinstaller...)
2. Build `dist/minifra-hub.exe` and `dist/minifra-agent.exe` (takes ~2 min)
3. Generate a self-signed TLS certificate so the browser can connect

---

## Step 3 — Start the Hub

```
dist\minifra-hub.exe
```

You should see:
```
INFO  Minifra Hub 2.4.1 started on port 8080
INFO  Collector started — 4 endpoints, interval 30s
INFO  Collecting from MFS-VM-01 (192.168.1.134)
```

The Hub is now polling all 4 VMs every 30 seconds via WinRM.

---

## Step 4 — Trust the certificate (once)

Open in your browser:

```
https://192.168.1.109:8080/health
```

Click **Advanced → Proceed anyway** to accept the self-signed cert.  
You should see: `{"status":"ok","version":"2.4.1",...}`

---

## Step 5 — Connect the Secure Console

In **Minifra Secure Console** → **Config → Hub tab**:

| Field | Value |
|---|---|
| Hub URL | `https://192.168.1.109:8080` |
| Auth Token | *(the token from hub-config.json)* |

Hit **Save**. The status bar at the top will flip from amber to teal: **HUB LIVE**.

---

## Step 6 — Deploy agents to the 4 VMs (optional but recommended)

WinRM agentless collection works immediately (Steps 1–5).  
The agent provides richer data: real-time process detection, USB events, CPU/RAM metrics.

```
python build\deploy.py
```

This will:
- Upload `minifra-agent.exe` to `C:\Program Files\MinifraSecure\` on each VM  
- Register and start the **MinifraAgent** Windows Service  
- Agents then push data to Hub every 30 seconds

To uninstall agents from all VMs:
```
python build\deploy.py --remove
```

---

## WinRM prerequisites (if not already configured)

Run these on each VM as Administrator:

```powershell
Enable-PSRemoting -Force
Set-Item WSMan:\localhost\Service\Auth\Basic $true
Set-Item WSMan:\localhost\Service\AllowUnencrypted $true
netsh advfirewall firewall add rule name="WinRM" dir=in action=allow protocol=TCP localport=5985
```

## What data is collected via WinRM

| API Endpoint | Data Source |
|---|---|
| `/api/v1/agents` | `Get-ComputerInfo`, hostname, OS, IP, user |
| `/api/v1/alerts` | Windows Security Event Log (IDs: 4625, 4648, 4688, 4698, 4740) |
| `/api/v1/proxy/traffic` | `Get-NetTCPConnection` — live established connections |
| `/api/v1/proxy/dlp` | Removable drives (`Win32_LogicalDisk`, DriveType=2) + blocked domains |
| `/api/v1/user-risk` | Computed from event log activity per user |
| `/api/v1/vault` | Populated by agents when installed |

  .134/VM-01  .141/VM-02  .142/VM-03  .143/VM-04

          minifra-hub.exe

                 │ HTTPS REST API
                 ▼
